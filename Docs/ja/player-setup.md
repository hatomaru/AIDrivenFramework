# プレイヤー向けAIセットアップ

UIは `AIDrivenSetup.unity` の編集可能なuGUI Canvasに配置しています。Play前から `AI Setup Canvas > Glass Card` 配下で、全8スライド・文字・ボタン・入力欄・ファイル一覧の表示枠を編集できます。Canvasのコントローラーを選ぶとInspectorから各スライドをプレビューできます。実行時は保存済みパネルの切替、データ更新、既存オブジェクトのアニメーションを行います。グラデーション・滑らかなアイコン・ガラス背景は保存済みSpriteです。日本語・英語フォントはOFLのNoto Sans JPを利用条件と共に同梱しています。カード上部の4段階バーで設定全体の進み具合を表示し、取得中は別途取得済み・残り容量を表示します。Editorメニューの再構築はシーンを置き換えるため、独自の配置変更は先に保存してください。

日本語・英語で使える任意導入の `AIDrivenSetup` シーンです。1画面1目的で「紹介 → 内容確認と同意 → 準備 → 完了」と進みます。モデル変更や持ち込み設定は独立した画面です。取得容量・通信先・両方の利用条件を確認し、「同意して準備する」を選ぶと、取得から実際の応答確認まで進みます。ゲームから追加ロードした場合、完了後は自動でゲームへ戻ります。

プログレスバーは設定全体の目安です。ソフト準備が0～25%、モデル取得が25～85%、実際の応答確認と保存が85～100%。取得中のモデル層ごとの容量を合算し、同じ試行では後戻りせず、検証と保存が成功した場合だけ100%になります。残り時間の予測ではありません。現在の工程、複数ファイルを合算した取得済み容量と残り容量も表示します。全容量がまだ確定していない間はconfigの見込みを使い「約」と表示します。導入済みモデルや手持ちGGUFではダウンロード不要と案内します。

青・紫・淡いピンクがゆっくり移ろう背景に、背景をガウスぼかししたガラスのカードを重ねます。文字の読みやすさを守るため、白を84%合成しています。ゲームのカメラ映像をぼかす機能ではなく、この設定画面の背景に対する表現です。輪郭のカバレッジ処理・4倍解像度・ミップフィルタで滑らかにしたグラデーションアイコンの小さな浮遊、控えめな画面切替、ボタンの押し込み、完了時の小さな光が動きます。**「動きを減らす」は初期状態でオフ**。明示的に保存した設定は尊重し、オンにするとこれらの動きを止めます。画像はコードから一度だけ生成し、背景の再描画は最大30 Hz、画面を閉じた際に解放します。

配色はWCAGの相対輝度で検査します。主要ボタン7.04:1、無効ボタン7.39:1、リンクのホバー6.04:1を確保しました。ガラス上の補助文字も、背景が仮に黒でも5.71:1以上です。`python Tools/check_setup_contrast.py` と、実際の描画スタイルの検査で確認できます。

初回表示だけでは、ソフトやモデルのダウンロード、プロセス起動、同意の保存を行いません。PC内の設定と、起動済みOllamaの導入済みモデル情報だけを確認します。「今はやめる」を選ぶと初期化は `false` を返します。ゲーム側で再試行・終了・AIなしの遊び方などを案内してください。


### llama.cppのZIPから準備する

Windows用のllama.cpp実行ソフトZIPと、GGUFモデルを選びます。セットアップがUI外でZIPを確認し、1つの `llama-server.exe` と対応するWindows／実行環境の種類を確認して、解凍サイズを表示します。ソースコードZIP、複数種類の実行ソフト、対応しない実行ファイルは理由を案内します。従来の設定に保存された導入済み実行ファイルのパスも引き続き読めます。

利用条件への明示同意後、確認時のSHA-256とZIPを照合し、ゲームの保存領域 `persistentDataPath/AIDrivenFramework/LlamaRuntime` 内の一時フォルダーへ非同期で解凍します。DLL・ライセンス・第三者通知を含む全ファイルを、元のフォルダー構成のまま保持します。完了解凍先を確定してから実際の応答を確認し、成功した場合だけ取り出した実行ファイルのパスを保存します。元ZIPと以前の設定は保持します。SHA-256は確認後の変更を検出するためのもので、配布元の真正性を保証するものではありません。画面の公式リリースへの案内から取得してください。

進捗画面はダウンロードと解凍を区別し、解凍済み・残り容量を表示します。解凍には15分の制限があり、中断できます。失敗・中断時は今回の一時ファイルだけを可能な範囲で片付けます。権限で消せないファイルは残る場合があります。OSの読み込み自体がすぐ止まらない場合も、画面の待機を解除し、後から設定を保存しません。危険なパス・リンク・重複／衝突する名前、1万件超の項目、5 GiB超の展開を拒否し、展開量＋64 MiBの空きを確認します。ZIP破損、実行ソフトなし、種類違い、容量不足、権限、確認後の変更も案内し、ファイル選択から再試行できます。解凍後の応答確認で失敗する場合は、GPU向けの依存関係を確認するか対応するCPU版ZIPを選んでください。

## モデルと利用条件

### ゲームのconfigを使用

モデル一覧は `AIDrivenConfig.Instance.OllamaRecommendModelInfos` から取得します。`ModelInfoConfig` の `ModelName`・`DownloadUrl`・`EstimatedDownloadBytes`・`LicenseUrl`・`Level` が画面へ反映されます。編集場所は **Tools > AIDrivenFW > Settings > Model** です。GGUFの配布ページへの案内には `RecommendModelInfos` の先頭を使います。プレイヤーの選択済み設定は別途 `ModelInfo` から復元します。

新規configの初期値は下記のQwen3ですが、既存・カスタムのモデル一覧は上書きしません。ゲームを配布する前に、新しい容量・利用条件の項目を設定してください。未設定なら確認画面へ進み、別モデルの条件や容量を推測して流用しません。

### Ollamaとllama.cppを選ぶ

両方が利用可能な場合、「続ける」で **かんたん自動準備（Ollama）／手持ちのモデルを使う（llama.cpp / GGUF）** を明示的に選びます。「モデル・実行方法を変更」からも選べます。選んだ方式だけを準備・保存し、もう一方の導入状態は変更しません。

llama.cppは、実行ソフトとGGUFモデルをセットアップ内のファイルブラウザーで選びます。フォルダー・GGUFモデル・llama-serverをグラデーション付きのベクターアイコンと文字で区別し、別の種類は選択できません。ホーム・ダウンロード・ドライブ・上の階層への移動、ファイル名による絞り込みを使えます。実行ソフトはチップ、モデルは積層のアイコンです。アイコンは名前・拡張子による分類です。一覧取得と選択ファイルの容量確認はUIとは別のスレッドで行います。読み込み中は動くバーと確認件数を表示し、不明な完了率は表示しません。移動・戻る操作で古い要求をキャンセルし、遅れて返った結果を無視します。絞り込みの連続入力をまとめ、保持件数を制限し、行を分割して描画します。15秒で再試行・別の場所を案内します。OS側の読み取りが即座に止められない場合でも、UIは待機せず、古い結果を反映しません。実際に動作するかは同意後の応答で確認します。実行ソフトはDLL・ライセンス通知を含めて展開し、モデルは指定した場所に保管してください。現在のllama.cpp導入はファイル選択による案内で、自動取得ではありません。

**プレイヤーが利用条件のURLを入力する必要はありません。** 選択したモデル名に対応するconfigの `LicenseUrl` を使います。未設定・無効なURLは、配布ページや別モデルの条件で補完しません。Ollamaで条件ページが未登録なら、起動済みのローカルOllamaの `POST /api/show` から、そのタグの `license` 本文を取得します。2秒の制限と応答サイズ上限があり、Ollamaの起動・モデル取得・文章生成は行いません。本文はCanvasに配置した画面で、全文をページ送り・スクロールして確認できます。表示はプレーンテキストで、モデル変更や戻るで古い応答を無効にします。

ページも本文も取得できない場合はリンクを非表示にし、**モデルの入手元でライセンスを手動確認してから同意する**よう日英で案内します。GGUFもconfigの明示的な `LicenseUrl` だけを使い、配布ページやファイル名から条件を推測しません。同意は初期オフで、メタデータ確認中は操作できず、利用条件を開閉するだけでは同意されません。手動確認の記録はOllama／GGUFの両方で保存でき、取得した本文はSHA-256も記録します。ファイル・モデル変更時は関連付けと同意を解除します。

- 最初の選択はQwen3 0.6B（約523 MB）。ダウンロードを小さくし、ゲームに使うメモリを残すための選択です。
- 1.7B（約1.4 GB）・4B（約2.5 GB）、別のローカルOllamaモデル、手持ちのllama-server/GGUFファイルも選べます。大きいほどメモリを使い、遅くなる場合があります。
- 推奨Qwen3のApache 2.0ライセンスと、実行ソフトの条件を別々に表示します。利用条件はconfigの明示的なリンク、Ollamaの本文、または入手元での手動確認で案内します。任意モデルのライセンス適合性を自動保証する機能ではありません。
- ゲームへモデルや実行ソフトを同梱しません。利用者のPCへ上流から取得します。取得物に含まれるライセンス・通知を保持してください。各ゲームの配布条件は別途確認してください。
- コードで描く抽象的なアイコンと、OSに導入されたフォントを使います。新たな第三者の画像や商用フォントファイルは再配布しません。日本語表示には日本語対応のOSフォントが必要です。

モデルの取得はOllamaの配信サーバー、実行ソフトの取得はGitHubを使います。ローカルAIへの入力は `127.0.0.1` へ送ります。クラウドモデルは対象外です。ゲームの他のオンライン機能までオフラインになるという意味ではありません。

## 動作環境と中断

起動済みOllamaを優先して使います。Windows x64で未導入の場合、固定版の公式ZIPを容量・SHA-256検証後に安全な一時フォルダへ展開し、ゲームの保存用フォルダへ配置します。管理者権限・グローバルPATH変更は不要ですが、OSやファイアウォールの確認が出る場合があります。

macOS、Linux、Windows ARMでは導入済みのローカルOllamaを利用できます。未導入時は[公式の導入ページ](https://ollama.com/download)と必要なOS操作を案内します。これらのOSの自動取得は未対応です。

「準備を中断」は現在の処理を止めます。Ollamaの取得済みモデルデータは再開に利用します。実行ソフトの未完了ZIPは削除するため、再取得は最初から始まります。再起動後も前回の選択を復元しますが、再開には改めて確認・同意が必要です。準備完了の設定は、短い挨拶を実際に生成できてから保存します。失敗しても以前の正常な設定は上書きしません。

## 動作確認手順

1. Unity Test RunnerのEditModeで `AIDrivenFW.Tests.Unit` 全体を実行します。同意前の副作用禁止、処理順、選択の固定、中断・再開、失敗時の保存禁止、容量不足、アーカイブの検証が対象です。
2. `python Tools/package_aisetup.py` で配布物を再生成し、クリーンなUnity 6000プロジェクトへインポートします。Scene・Script・Stylesheet・Themeの参照とコンパイルを確認します。
3. 小さなゲームシーンから `AIDrivenInitializer.Initialize()` を呼び、AISetupをBuild Settingsへ追加してWindows x64 Playerをビルドします。
4. 同意前は開始ボタンが無効で、取得やプロセス起動を行わないことを確認します。日英切替、モデル選択後の同意解除、利用条件リンク、キーボード操作、「動きを減らす」、1440×900／900×700表示とスクロールを確認します。
5. 拒否で `false`、同意後の実応答・設定保存・ゲーム復帰で `true`、次回起動の準備済みスキップを確認します。
6. 通信断・中断・再起動・存在しないモデル・空き容量不足・実行権限不足・非対応モデルを試し、回復案内と既存設定の保持を確認します。
7. Ollamaのない隔離されたWindows x64環境でも、公式ZIPの取得・検証・展開・起動から実生成と次回復元まで確認します。導入済みサービスでの成功と、未導入環境での実証は区別してください。

導入済みOllamaと `qwen3:0.6b` があるWindows環境では `Tools/UnityValidation/run.ps1 -Unity <Unity.exe>` で新しい隔離プロジェクトを作り、配布物のインポート・EditModeテスト・Playerビルド・実生成・進捗・復帰を再現できます。既存フォルダは初期化しません。

固定版・ハッシュ・保存場所・配布ソース・詳しい検証範囲は[英語版ガイド](../player-setup.md)を参照してください。実施済み結果と未検証環境はPRに記載します。
