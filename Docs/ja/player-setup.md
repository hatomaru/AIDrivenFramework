# プレイヤー向けAIセットアップ

日本語・英語で使える任意導入の `AIDrivenSetup` シーンです。1画面1目的で「紹介 → 内容確認と同意 → 準備 → 完了」と進みます。モデル変更や持ち込み設定は独立した画面です。取得容量・通信先・両方の利用条件を確認し、「同意して準備する」を選ぶと、取得から実際の応答確認まで進みます。ゲームから追加ロードした場合、完了後は自動でゲームへ戻ります。

プログレスバーは設定全体の目安です。ソフト準備が0～25%、モデル取得が25～85%、実際の応答確認と保存が85～100%。取得中のモデル層ごとの容量を合算し、同じ試行では後戻りせず、検証と保存が成功した場合だけ100%になります。残り時間の予測ではありません。アニメーションは短い画面切替に絞り、「動きを減らす」で無効にできます。

配色はWCAGの相対輝度で検査します。主要ボタン7.04:1、補助文字8.31:1、無効ボタン7.39:1、リンクのホバー6.04:1を確保しました。`python Tools/check_setup_contrast.py` と、実際の描画スタイルの検査で確認できます。

初回表示だけでは、ソフトやモデルのダウンロード、プロセス起動、同意の保存を行いません。PC内の設定と、起動済みOllamaの導入済みモデル情報だけを確認します。「今はやめる」を選ぶと初期化は `false` を返します。ゲーム側で再試行・終了・AIなしの遊び方などを案内してください。

## モデルと利用条件

- 最初の選択はQwen3 0.6B（約523 MB）。ダウンロードを小さくし、ゲームに使うメモリを残すための選択です。
- 1.7B（約1.4 GB）・4B（約2.5 GB）、別のローカルOllamaモデル、手持ちのllama-server/GGUFファイルも選べます。大きいほどメモリを使い、遅くなる場合があります。
- 推奨Qwen3のApache 2.0ライセンスと、実行ソフトの条件を別々に表示します。カスタムモデルにはHTTPSのライセンスURLを指定してください。任意モデルのライセンス適合性を自動保証する機能ではありません。
- ゲームへモデルや実行ソフトを同梱しません。利用者のPCへ上流から取得します。取得物に含まれるライセンス・通知を保持してください。各ゲームの配布条件は別途確認してください。
- 図形による相棒と、OSに導入されたフォントを使います。新たな第三者の画像や商用フォントファイルは再配布しません。日本語表示には日本語対応のOSフォントが必要です。

モデルの取得はOllamaの配信サーバー、実行ソフトの取得はGitHubを使います。ローカルAIへの入力は `127.0.0.1` へ送ります。クラウドモデルは対象外です。ゲームの他のオンライン機能までオフラインになるという意味ではありません。

## 動作環境と中断

起動済みOllamaを優先して使います。Windows x64で未導入の場合、固定版の公式ZIPを容量・SHA-256検証後に安全な一時フォルダへ展開し、ゲームの保存用フォルダへ配置します。管理者権限・グローバルPATH変更は不要ですが、OSやファイアウォールの確認が出る場合があります。

macOS、Linux、Windows ARMでは導入済みのローカルOllamaを利用できます。未導入時は[公式の導入ページ](https://ollama.com/download)と必要なOS操作を案内します。これらのOSの自動取得は未対応です。

「準備を中断」は現在の処理を止めます。Ollamaの取得済みモデルデータは再開に利用します。実行ソフトの未完了ZIPは削除するため、再取得は最初から始まります。再起動後も前回の選択を復元しますが、再開には改めて確認・同意が必要です。準備完了の設定は、短い挨拶を実際に生成できてから保存します。失敗しても以前の正常な設定は上書きしません。

## 動作確認手順

1. Unity Test RunnerのEditModeで `AIDrivenFW.Tests.Unit` 全体を実行します。同意前の副作用禁止、処理順、選択の固定、中断・再開、失敗時の保存禁止、容量不足、アーカイブの検証が対象です。
2. `python Tools/package_aisetup.py` で配布物を再生成し、クリーンなUnity 6000プロジェクトへインポートします。Scene・Script・Stylesheet・Themeの参照とコンパイルを確認します。
3. 小さなゲームシーンから `AIDrivenInitializer.Initialize()` を呼び、AISetupをBuild Settingsへ追加してWindows x64 Playerをビルドします。
4. 同意前は開始ボタンが無効で、取得やプロセス起動を行わないことを確認します。日英切替、モデル選択後の同意解除、利用条件リンク、キーボード操作、「動きを減らす」、1440×900／900×700表示とスクロールを確認します。
5. 拒否で `false`、同意後の実応答・設定保存・ゲーム復帰で `true`、次回起動の準備済みスキップを確認します。
6. 通信断・中断・再起動・存在しないモデル・空き容量不足・実行権限不足・非対応モデルを試し、回復案内と既存設定の保持を確認します。
7. Ollamaのない隔離されたWindows x64環境でも、公式ZIPの取得・検証・展開・起動から実生成と次回復元まで確認します。導入済みサービスでの成功と、未導入環境での実証は区別してください。

導入済みOllamaと `qwen3:0.6b` があるWindows環境では `Tools/UnityValidation/run.ps1 -Unity <Unity.exe>` で新しい隔離プロジェクトを作り、配布物のインポート・EditModeテスト・Playerビルド・実生成・進捗・復帰を再現できます。既存フォルダは初期化しません。

固定版・ハッシュ・保存場所・配布ソース・詳しい検証範囲は[英語版ガイド](../player-setup.md)を参照してください。実施済み結果と未検証環境はPRに記載します。
